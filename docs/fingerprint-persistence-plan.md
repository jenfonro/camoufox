## 目标与职责

长期画像的目标是：同一档案在相同输入与运行条件下跨启动保持稳定，
不同档案可以由不同输入产生不同结果。默认行为与显式配置的边界仍
按照现有 Camoufox 通用接口设计，不加入特定管理器的业务数据结构。
用户要求验收网站上基本所有稳定画像值，而非只验证 Canvas：未手动
更改档案设置时，正常关闭重开后这些字段应保持不变。动态时间、实际
网络与站点会话信息按其本来含义变化，稳定字段变化必须查明原因。
用户再次明确严格验收：纳入画像范围的完整哈希必须精确不变，不能
用短前缀比较、整体评分或“绝大部分相同”放宽。天然动态项预先列明，
不能事后将漂移的画像字段移出验收；具体通过条件见持久化分析。

管理器负责保存并回放完整画像、种子和行为开关；内核负责让给定输入
在对应的原生接口和执行路径上确定地生效。这里不新增一套档案数据库，
也不把网站生成的哈希作为需要直接写入内核的数据。

浏览器原生的用户目录继续承载 Cookie、localStorage、会话等状态。
这些既有账号数据与本阶段的指纹稳定性分开处理，不用清空目录做测试。

## 实施前确定的优先级

| 项目 | 当前依据 | 下一步工作 |
| --- | --- | --- |
| Canvas 2D 与 WebGL 图像导出 | `canvas:seed` 在 schema 和 Python 层存在，但当前受版本管理的源码补丁及 additions 没有读取入口；已有记录指出图像导出带有会话变化 | 首先补齐可固定输入的原生路径，覆盖图像读取、导出、OffscreenCanvas 等相关入口，验证同档案稳定和跨档案区分 |
| Audio | `audio:seed` 已由 `AudioFingerprintManager` 消费并用于确定性变换 | 回放既有种子，验证不同读取方法、重复读取与跨启动一致性，再决定是否存在内核缺口 |
| 字体与布局 | `fonts`、`fonts:spacing_seed` 已有接口；通用回归记录了 ClientRects 漂移 | 固定字体列表及种子；先定位已知布局漂移的具体原因，不直接假定需要新噪声参数 |
| WebGL 参数画像 | 厂商、型号、参数、扩展等已有配置 | 回放完整参数，与 Canvas/WebGL 图像导出策略联合回归；参数报告和像素结果分别验证 |
| WebGPU | 三个新入口已实现，测试画像在重启和本机 GPU/WARP 下报告一致 | 纳入统一画像保存/回放清单和回归，沿用已完成实现，不重复创建另一套 WebGPU 画像协议 |
| 其余静态画像 | 窗口画像、navigator、语音列表和媒体设备等各有现有配置 | 纳入配置完整性清单，按实际需要验证；不把所有字段默认变成新内核功能 |

第一步重点是 Canvas 及 WebGL 图像导出的固定输入。已有
`docs/per-context-patches.md` 描述过 CanvasFingerprintManager 和
canvas-spoofing.patch，但当前源码集合中未找到这些实现；后续以实际
代码与当前构建的证据为准，不以文档中曾出现字段视为功能已实现。

已有 Nimbo 调查记录显示，简单关闭基线 Canvas 随机化虽可能令同一
档案稳定，也可能令不同档案的纯图形输出相同。这是本阶段需要解决的
问题，不能仅以关闭保护作为完成标准。具体随机化入口、种子范围和
跨站点语义将在读取当前 Firefox 代码后确定，不因上述范围清单提前
宣称所有图像路径均已支持。

## WebGPU 应纳入的配置

同一档案至少应保持以下配置的选择一致：

- `gfx:hardwareAcceleration`：图形加速许可，属于执行策略。
- `webgpu:enabled`：是否暴露接口，属于行为策略。
- `webgpu:profile`：整份画像，包括 `gpu`、`adapter` 和
  `adapterOverrides`，属于对外身份和能力数据。

这些字段由管理器完整存储、原样传入即可使用已有内核实现。显式开放
但未传画像仍按既定规则返回原生值；部分画像未覆盖的值仍可能跟随
环境，不将其误称为完整跨机器持久化。

## 验证边界

实施前确定的工作包括：Canvas 原生固定输入、种子类型与
缺省/零值语义、生命周期与档案隔离、Audio/字体/ClientRects 的稳定性
缺口，以及完整网站报告的严格验收清单。这些工作现已实施并验证，
历史依据见持久化分析的闭环清单；
没有新增管理器专属参数或移植参考项目整套实现的要求。

先使用已记录的结果和当前源码确定缺口，再进行有针对性的验证：
同档案同输入重启、不同档案不同输入、重复读取、跨页面和 Worker、
启用/关闭后的默认兼容性，以及与现有窗口、WebGPU 功能的组合。
指纹结果使用 BrowserScan 实际显示值，并结合必要的原生功能一致性
测试。不以单次哈希不同或相同替代完整判断，也不承诺任意 GPU、驱动、
字体渲染环境的像素天然一致。
